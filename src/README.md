# 소스 구조

게임은 여기 `src/`에서 고치고, 저장소 맨 위에서 `python build.py`로 합친다. 합친 결과(`index.html`, `game.css`, `game.js`, `lazy/`)를 GitHub Pages가 그대로 보여 준다. 합친 파일은 직접 고치지 않는다.

```
src/
  shell.html      화면의 기본 틀(첫 화면 글, 참가자 정보 칸). <!--@CSS-->와 <!--@JS--> 자리에 빌드 결과가 들어간다
  css/            처음부터 받는 디자인. 파일 이름 순서대로 이어 붙인다
  js/             처음부터 받는 코드. 파일 이름 순서대로 이어 붙여 (function(){ … })(); 하나로 감싼다
  lazy/<이름>/    나중에 받는 조각. 코드(.js)와 그 화면에서만 쓰는 디자인(.css)
```

## 처음부터 받는 코드(`js/`)

한 함수 안에 들어가므로 파일끼리 변수를 그대로 쓴다. 맨 바깥에서 바로 실행되는 줄(함수 안이 아닌 곳)은 파일 순서대로 실행되니, 앞 파일에서 뒤 파일의 `const`/`let`을 바로 쓰면 안 된다(함수 선언은 어디서나 쓸 수 있다).

## 나중에 받는 조각(`lazy/`)

| 조각 | 내용 | 받는 때 |
|---|---|---|
| `guide` | 가이드북 | 가이드북을 열 때 |
| `sports` | 양궁·수영·승부차기·태권도, 직접/시뮬레이션 고르기, 시상식 | 올림픽 종목 단계 |
| `slash` | 백신 슬래시(현장 지휘) | 방역 특집 현장 지휘 단계 |
| `board` | 게임 안 명예의 전당(예전 전체 화면 순위표 포함) | 명예의 전당을 열 때 |
| `door` | 문 소리 데이터 | 소리를 처음 켤 때 |

가이드북·미니게임·명예의 전당은 첫 화면이 뜨고 2.5초쯤 뒤 쉬는 틈에 미리 받아 두므로, 보통은 기다릴 일이 없다.

- 조각 안의 함수를 조각 밖에서 부르면, 빌드가 같은 이름의 '대신 부르기' 함수를 만든다. 처음 부르면 조각을 받은 뒤 진짜 함수를 부른다. 그래서 처음 한 번은 결과가 바로가 아니라 조금 뒤에 나온다.
- 조각 밖에서 조각 안의 `const`/`let`을 쓰면 빌드가 멈춘다. 그 값은 `js/`로 옮긴다.
- 결과를 바로 돌려받아야 하는 함수(예: 시뮬레이션)를 다른 조각에서 부를 때는, 먼저 `lzThen('조각', fn)`으로 그 조각을 받아 둔다(`mgRun`의 `lz` 참고).
- 조각 코드는 `js/00a-lazy.js`의 `lzRun` 안에서 실행되어, 처음부터 받는 코드의 변수를 그대로 쓴다. 조각 파일은 지문(SHA-256)이 맞을 때만 실행된다.
- 못 받으면 화면 아래에 '다시 시도'가 뜬다. 게임이 새 버전으로 바뀐 직후 예전 화면과 새 조각이 섞이면 '새로고침'이 뜬다.

## 명령

```
python build.py                    만들기
python build.py --check            만든 파일이 src/ 와 맞는지 확인(커밋 전에)
python build.py --single 경로.html  모든 것을 한 파일에 넣은 판(인터넷 없이 열어 보기·바탕화면 사본)
python tools/jsdeps.py [조각]       조각끼리 주고받는 이름 보기
```
